# Чек-листы (PR / релиз)

## Jules-ready (task header перед запуском задачи)
- [ ] **Title**: `feat|fix: <модуль>: <кратко>`
- [ ] **Branch**: `feature/<slug>`
- [ ] **Scope/Files**: перечислить файлы; не более **20** файлов, ≤ **300** строк diff
- [ ] **Rules**: `unified diff only`, **no binaries** (CSV/PNG > 5 MB — только как артефакты CI)
- [ ] **Sequential PRs**: серия задач запускается **последовательно**
- [ ] **CI команды**: `pytest --cov`, смоук-бэктест; артефакты в `reports/`
- [ ] **KPI impact**: Sharpe, PF, Max DD, Win-Rate — ожидание/допуски
- [ ] **Acceptance**: PR открыт, Checks зелёные, отчёты приложены
- [ ] **Rollback**: план отката (revert/feature-flag/Safe-Mode)
- [ ] **Backup**: дифф продублирован текстом в чате (на случай зависания UI)

## PR-чек-лист
- [ ] Цель и влияние на KPI (Sharpe, PF, Max DD) сформулированы
- [ ] Изменения по файлам перечислены; миграции/флаги указаны
- [ ] Юнит-тесты добавлены/обновлены; **coverage ≥ 90%**
- [ ] Смоук-бэктест выполнен; отчёты в `reports/` приложены
- [ ] Конфиги синхронизированы с `unified_config*.json`
- [ ] Нет секретов/персональных данных в коде и логах
- [ ] Документация/roadmap обновлены при изменении логики
- [ ] План отката описан (revert/feature-flag/Safe-Mode)
- [ ] Diff‑патч и описание задачи подготовлены в формате, удобном для Jules (атомарность, ясные шаги)

## DoD для PR
- CI зелёный: `pytest --cov` + смоук-бэктест OK
- Метрики не деградируют вне допусков
- Логи понятны; дубликаты отфильтрованы

## Релиз-чек-лист
- [ ] Все обязательные PR слиты в защищённые ветки
- [ ] Теги/релиз-ноутсы: изменения, риски, откат
- [ ] Конфиги окружений зафиксированы (prod/stage)
- [ ] Мониторинг и алерты проверены (Safe-Mode/CB/Max DD)
- [ ] Отчёты за период собраны (NAV, Sharpe, PF, DD)
- [ ] План пост-релизного аудита (1–3 дня)

## Политика безопасности
- Секреты — только в Secrets CI/репозитория
- Никаких ключей/токенов/ID в коде, патчах и публичных отчётах

## Примечание по стабильности UI Jules
- При зависании интерфейса: ориентир на GitHub PR/Actions как SoT.
- Всегда требовать у модели **текст unified diff** и команды применения.
