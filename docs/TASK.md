Архитектура системы «Бот + Бэктестер + Оптимизатор»

Система состоит из трёх ключевых компонентов: торгового бота, бэктестера и модуля оптимизации (Optuna). Все параметры стратегии хранятся исключительно в едином конфигурационном файле unified_config.json
GitHub
. Торговый бот периодически читает сигналы и выполняет сделки, бэктестер моделирует историю торгов с учётом этих сигналов, а оптимизатор настраивает параметры стратегии при помощи Optuna.

Торговый бот (SignalBot)

Торговый бот загружает настройки из unified_config.json и управляет реальными сделками в соответствии с целевыми весами активов, порогами ребаланса, стопами и другими параметрами, заданными в конфиге
GitHub
. Генерация торговых сигналов производится вспомогательным модулем (SignalBot), который получает рыночные данные (через DataLoader), рассчитывает индикаторы и сохраняет сигналы в CSV‑файлы вида graphs/<SYMBOL>_signals.csv
GitHub
. При этом каждая запись в файле содержит таймштамп, символ и тип сигнала. Торговый бот периодически считывает эти файлы с сигналами и на их основе открывает или закрывает позиции в соответствии с текущей конфигурацией. При изменении сигнала бот может обновлять распределение активов (asset distribution) в конфиге ребалансера, основываясь на секции «последних сигналов».

Модуль бэктестера (futures_rebalance_backtester.py)

Новый модуль futures_rebalance_backtester.py полностью заменяет ранее используемые rebalance_backtester.py и futures_backtester.py. Этот бэктестер запускает симуляцию стратегии дельта‑нейтрального ребаланса на исторических данных. Все параметры (комиссии, левередж, начальный баланс, «цельные» доли, пороги ребаланса, настройки Circuit Breaker/Safe Mode и пр.) берутся из unified_config.json
GitHub
. Входными данными для бэктестера служат исторические цены (загружаемые через DataLoader по путям из конфига) и заранее сгенерированные сигналы из файлов graphs/*_signals.csv (каждому символу соответствует свой файл)
GitHub
. Бэктестер последовательно эмулирует торговые циклы: в момент каждого тика он проверяет сигналы, открывает/закрывает позиции, рассчитывает P&L, учитывает TP/SL, торгуемые комиссии и пр., и строит временной ряд Equity-кривой.

По завершении прогонки формируются сводные отчёты с показателями эффективности (KPI) и журналом сделок. Результаты сохраняются в директорию reports/ в подпапку с меткой времени, например reports/backtest_<TIMESTAMP>/. В этой папке генерируются файлы summary.csv (итоговые KPI и параметры), trades.csv (список сделок) и графический дашборд с кривыми доходности
GitHub
. Таким образом, каждый прогон бэктестера оставляет полный артефакт отчётности в reports/
GitHub
.

Модуль оптимизации (Optuna)

Оптимизация параметров стратегии выполняется модулем на базе Optuna (скрипт rebalance_optimizer.py). Оптимизатор читает настройки из секции optimizer_settings того же файла unified_config.json
GitHub
: число испытаний (n_trials), целевую метрику (например, Sharpe или Profit Factor), направление оптимизации и пространство параметров для подбора (например, порог ребаланса, минимальный нотионал, таргетные доли активов). Optuna многократно запускает бэктестер с разными комбинациями параметров и ищет набор, максимизирующий выбранную метрику.

Процесс оптимизации может запускаться автоматически по расписанию: например, раз в сутки или при заметном ухудшении ключевых показателей стратегии. После каждой сессии оптимизации лучшие параметры временно сохраняются и тестируются в течение контрольного периода (обычно 72 часа) для валидации стабильности. Новые параметры применяются к стратегии только после успешной валидации в течение 72 часов: то есть, если в течение трёх дней на исторических или свежих данных они продолжают показывать улучшение метрик, то их можно считать надёжными.

При этом в unified_config.json предусмотрен флаг auto_apply_optimized_config. Если он установлен в true, то по завершении оптимизации система автоматически переписывает секцию параметров в unified_config.json на найденные оптимальные значения. В противном случае изменения в конфиг вносятся вручную после одобрения. Все результаты работы оптимизатора (лог выполнения Optuna, история испытаний, важности параметров и прочие графики) сохраняются в отдельную подпапку reports/optimizer_run_<TIMESTAMP>/ вместе с файлами optimization_log.csv и best_params.json
GitHub
. Таким образом в reports/ хранится полный набор артефактов и логов как бэктестера, так и оптимизатора
GitHub
.

Конфигурация и данные

Единая конфигурация unified_config.json является «источником правды» для всех компонентов системы
GitHub
. В ней задаются настройки как бэктеста (раздел backtest_settings), так и оптимизации (optimizer_settings). Никакие параметры не хардкодятся в коде: все пороги, доли и пр. считываются только из конфига. Исторические рыночные данные передаются бэктестеру в CSV-файлах (их путь задаётся в конфиге). Сами сигналы торговый бот генерирует на основе свежих котировок и сохраняет в graphs/*.csv
GitHub
, после чего бэктестер и другие модули используют эти сигналы.

Отчёты и артефакты

Все результаты работы компонентов пишутся в каталог reports/. Каждый запуск бэктестера создаёт папку вида reports/backtest_<TIMESTAMP>/ с итоговыми CSV и HTML-отчетами
GitHub
. Аналогично, оптимизатор создаёт папку reports/optimizer_run_<TIMESTAMP>/ с логами оптимизации и визуализациями (optimization_history.html и др.)
GitHub
. Дополнительно при необходимости хранятся отдельные отчёты по отдельным попыткам Optuna в подпапке trials/. Такая организация гарантирует, что все артефакты (результаты бэктестов, отчёты оптимизации, графики KPI и т.д.) централизованно доступны в reports/
GitHub
 для последующего анализа.
