Как мониторить объемы в стакане Binance для лимитных ордеров

Чтобы мониторить объёмы лимитных ордеров в стакане Binance, тебе нужно использовать глубину стакана (order book depth) через REST и/или WebSocket.

Ниже — как это сделать практик‑ориентированно, чтобы твой бот‑ребалансировщик мог читать объёмы и на них ориентироваться.

1. Типы данных стакана
Binance даёт два основных способа:

REST /depth — точечная снимок стакана (1 раз, не в реальном времени).

WebSocket @depth — стрим изменений стакана, чтобы поддерживать локальный book.

Оба возвращают уровни цены и объёма (bid/ask) — это то, что тебе нужно для мониторинга лимитных ордеров.

2. REST: один раз/по интервалу
Endpoint (Spot, пример):

text
GET /api/v3/depth
  ?symbol=BTCUSDT
  &limit=100
symbol — тикер, например ETHUSDT.

limit — сколько уровней стакана получить: 5, 10, 20, 50, 100, 500, 1000 и т.д.

Ответ выглядит так:

js
{
  "bids": [ ["price", "qty"], ... ],
  "asks": [ ["price", "qty"], ... ]
}
То есть для каждого уровня ты видишь:

цену (лимит)

объём (сколько лимиток «висит» в стакане)

Ты можешь, например, каждые 1–5 секунд дергать /depth и:

фильтровать уровни в нужном диапазоне (например, ±0.5% от текущей цены),

смотреть, есть ли объём ≥ X, чтобы твой ордер мог «снять» чужой лимит.


3. WebSocket: постоянный мониторинг
Чтобы не опрашивать REST‑лимитами, используй стрим:

text
<symbol>@depth<levels>
или
<symbol>@depth
Пример для BTCUSDT:

text
btcusdt@depth
// или с лимитом уровней
btcusdt@depth50
WebSocket присылает диффы глубины стакана:

изменения в bids/asks (цена, объём),

тип события: u (update), a (add), r (remove).

Ты:

сначала делал один REST /depth (full snapshot),

дальше подсовываешь к нему диффы из @depth и получаешь полный, живой локальный стакан.

Это идеально для твоего бота:

ты видишь, какие уровни уже есть,

какой там объём,

и можешь решать, снимать ли этот чужой лимит или ждать.

4. Как именно мониторить объёмы
Для твоей логики «продать дороже / купить дешевле» можно сделать:

При продаже:

бери лучшие asks из локального стакана,

фильтруй по цене: например, price > current_price * (1 + 0.001),

проверь, qty ≥ 70–80% от твоего объёма продажи.

При покупке:

бери bids,

price < current_price * (1 - 0.001),

qty ≥ 70–80% от твоего объёма покупки.


Если условия по уровню/объёму выполняются — ты понимаешь, что почти наверняка можешь снять чужой лимит и получить выигрыш в цене.

5. Практические рекомендации для бота
Для каждого торгового инструмента:

поддерживай локальный стакан (REST + WebSocket @depth).

Параметры:

max_levels = 20–50,

min_qty_threshold (минимальный объём уровня, чтобы ты им пользовался).

Логика:

при каждом триггере ребалансировки смотри в стакан,

если есть подходящий уровень с достаточным объёмом — исполнить через маркет, чтобы снять чужой лимит,

если нет — либо ждать, либо перейти к более агрессивной стратегии.


Так ты будешь непрерывно мониторить объёмы чужих лимитных ордеров и использовать их для того, чтобы покупать дешевле и продавать дороже в рамках твоей стратегии ребалансировки.
