Для получения данных с Binance (как рыночных, так и пользовательских) существуют следующие способы, разделенные по протоколам и методам доступа:

  1. REST API (HTTP/HTTPS) — Стандартный метод
  Самый распространенный способ для получения «снимков» данных (Snapshot) и выполнения разовых запросов.
   * Market Data (Публичные): Цены, стаканы, история сделок, свечи (Klines), информация о тикерах.
   * Account Data (Приватные): Балансы, открытые позиции, история ордеров, история транзакций (требует API Key + Secret Key и подписи HMAC SHA256/RSA).
   * Подразделы: Spot API, Margin API, USDⓈ-M Futures API, COIN-M Futures API, Options API, Earn/Staking API, Pay API, P2P API.

  2. WebSockets (WSS) — Потоковые данные в реальном времени
  Используется для получения обновлений без задержек и постоянных запросов.
   * Public Streams:
       * Aggregate Trade Streams: Каждая сделка.
       * Kline/Candlestick Streams: Обновление свечей в реальном времени.
       * Individual Symbol Ticker Streams: Изменение цены за 24ч.
       * Order Book Streams: Обновления стакана (Diff. Depth) или частичные срезы (Partial Book Depth).
       * Liquidation Order Streams: Данные о ликвидациях на фьючерсах.
   * User Data Streams (Приватные):
       * Требуют создания listenKey через REST API. Позволяют мгновенно получать уведомления об исполнении ордеров, изменении баланса и обновлении позиций.

  3. FIX API (Financial Information eXchange) — Институциональный стандарт
  Протокол с низким временем задержки (Low Latency), используемый профессиональными трейдерами.
   * FIX 4.4: Поддерживается для Spot и Futures. Позволяет получать рыночные данные и управлять ордерами через бинарный или текстовый протокол TCP. Быстрее, чем классический REST API.

  4. Binance Data Collection (S3 / Исторические данные)
  Для глубокого бэктеста и анализа больших данных.
   * Binance Data (data.binance.vision): Публичный S3-репозиторий с историческими данными (CSV/Parquet) по дням и месяцам. Включает свечи, сделки (Trades), агрегированные сделки и глубину стакана.
   * Historical Data API: Платный сервис для получения архивных данных через специальные эндпоинты.

  5. GraphQL (Ограниченно)
  Используется в некоторых внутренних и новых сервисах Binance (например, Binance NFT или подсервисы через The Graph), но не является основным методом для трейдинга.

  6. RSS / Webhooks / Социальные каналы (Инфо-данные)
  Для получения нерыночных данных (листинги, новости, изменения в маржинальных требованиях).
   * Announcements RSS Feed: Новости о новых монетах.
   * Binance Support Telegram/Email: Официальные уведомления.

  7. Библиотеки-коннекторы (Wrappers)
  Официальные и комьюнити-библиотеки, которые инкапсулируют все вышеперечисленные методы:
   * Python: binance-connector-python, python-binance.
   * Node.js: node-binance-api.
   * Go, C++, Java, C#: Официальные SDK от Binance на GitHub.

  8. Binance Cloud / Broker API
  Специальные API для партнеров и тех, кто строит свои биржи на базе ликвидности Binance. Дают доступ к расширенным данным о пользователях и сетевой статистике.

  9. Инфо-виджеты и Embeds
  Для веб-мастеров: готовые iframe-виджеты для отображения цен и графиков на сторонних сайтах.

  ---
  Итог: Для вашего бота (Market Neutral) вы используете комбинацию REST API (для инициализации и сканера) и WebSockets (в перспективе для моментальной реакции, хотя в стратегии с циклом 30 сек REST API
  достаточно). Самый быстрый способ из всех — FIX API, самый информативный для анализа — S3 Data Dumps.
