# 🛡 Логика ребалансировки «Синхронные часы» (Версия 2.5.4)

Система управляет портфелем как единым математическим пространством, состоящим из четырех компонент: **Long (x5)**, **Short (x5)**, **Virtual (x1)** и **Cash**.

### 1. Математические инварианты
*   **Сумма весов:** $Weight_L + Weight_S + Weight_V + Weight_{Cash} \equiv 100.0\%$.
*   **Живая оценка:** Стоимость каждой реальной доли ($L$, $S$) рассчитывается как `Базовый залог + Нереализованный PnL`. 
*   **Рабочий TPV:** Общая стоимость портфеля (TPV) — это сумма текущих стоимостей всех компонент.

## 🗓 06 мая 2026: Протокол «Щит и Меч» (v2.5.4)

### ✅ Ключевые достижения:
1.  **Post-Stop Paper Probation:** После срабатывания трейлинг-стопа бот переходит в режим принудительной бумажной торговли на период `probation_period_days`. Это позволяет боту "переждать" волатильность, не теряя места в ротации, если он остается прибыльным.
2.  **State-Wide Fact Protocol:** Супервайзер теперь сканирует все файлы состояния (`state_*.json`), а не только запущенных ботов. Это гарантирует, что прибыльный бот, даже будучи остановленным, будет учтен в рейтинге и возвращен в ротацию (в бумажном или реальном режиме).
3.  **Trailing Stop Timeout (Confirmation):** Внедрена задержка подтверждения срабатывания трейлинг-стопа (`equity_trailing_stop_timeout_sec`) для защиты от кратковременных ценовых шпилек.
4.  **Dynamic Probation Sync:** Длительность после-стоповой пробации автоматически синхронизируется с глобальным параметром `probation_period_days`.
6.  **Log-Based Observability:** Внедрен модуль `visualize_bot_log.py` для детальной визуализации работы каждого тикера напрямую из его логов. Модуль отображает TPV, динамику весов портфеля и точки фиксации прибыли в SAFE.

## 🗓 07 мая 2026: Протокол «Адаптивный Рой» (v2.7.0)

### ✅ Ключевые достижения:
1.  **Delta-Based Rotation:** Внедрен 3-часовой алгоритм (на основе `backtest_period_days`) ранжирования ботов по $\Delta PnL$. Теперь DOGS и другие лидеры не являются «вечными» — ротация происходит динамически на основе наиболее прибыльных ботов за последний 3-часовой интервал.
2.  **Pruning Logic (Anti-Leak):** Добавлена автоматическая «зачистка» ботов (Fire Bot). Если за 3 часа бот показал убыток $\Delta PnL < -0.1$ USDT, он принудительно останавливается, а его файлы стейта переименовываются (`.fired`), что исключает его из ротации.
3.  **Decoupled Windows:** Периоды для ротации (3ч) и пробации новых ботов (1ч) теперь развязаны, что дает системе гибкость в оценке кандидатов без риска преждевременной потери стабильных ботов.
4.  **Selection Strategy:** ТОП-2 по дельте прибыли за 3 часа автоматически занимают REAL слоты, остальные прибыльные боты — в PAPER (или ожидают очереди).

## 🗓 08 мая 2026: Протокол «Стабильный Рой» (v2.7.5)

### ✅ Исправление критических ошибок:
1.  **Stop-Loop Elimination:** Исправлен бесконечный цикл «стоплосс-перезапуск». Теперь при любом стопе (Emergency/Trailing) бумажный баланс принудительно сбрасывается до `initial_capital` (65 USDT). Это гарантирует чистый старт бота.
2.  **Trailing Stop PnL Realization:** Внедрена корректная фиксация PnL в бумажный баланс при срабатывании трейлинг-стопа.
3.  **Cross-Platform Robustness:** Внедрена повсеместная поддержка UTF-8 с защитой от битых байтов (`errors='replace'`) для стабильной работы на Windows.
4.  **Atomic File Ops (Windows):** Исправлена ошибка `FileExistsError` при ротации ботов. Теперь старые `.fired` файлы перезаписываются корректно.
5.  **Paper Mode Sync Guard:** Исправлена рассинхронизация режимов при вызове `emergency_stop`, что исключает ошибочные действия на бирже.
