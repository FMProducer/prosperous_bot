# 🛡 Логика ребалансировки «Синхронные часы» (Версия 2.4)

Система управляет портфелем как единым математическим пространством, состоящим из четырех компонент: **Long (x5)**, **Short (x5)**, **Virtual (x1)** и **Cash**.

### 1. Математические инварианты
*   **Сумма весов:** $Weight_L + Weight_S + Weight_V + Weight_{Cash} \equiv 100.0\%$. Любое изменение цены перераспределяет доли, что позволяет системе точно фиксировать дрейф и инициировать ребалансировку.
*   **Живая оценка:** Стоимость каждой реальной доли ($L$, $S$) рассчитывается как `Базовый залог + Нереализованный PnL`. Виртуальная доля ($V$) трактуется как фиксированное количество монет, стоимость которого меняется вместе с рынком: $V_{current} = Qty_{virt} \cdot Price_{now}$.
*   **Рабочий TPV:** Общая стоимость портфеля (TPV) — это сумма текущих стоимостей всех компонент. $TPV = Real\_Equity + (V_{current} - V_{allocated\_at\_rebalance})$.

## 🗓 03 мая 2026: Протокол «Чистый Горизонт» (Rotation Safety Fix)

### ✅ Ключевые достижения:
1.  **Stop-Kill-Clean Protocol:** Исправлена критическая гонка (Race Condition) при ротации ботов. Теперь Супервайзер сначала принудительно убивает процесс PM2 (`pm2 delete`), и только после этого запускает скрипт очистки позиций. Это исключает ситуацию, когда «умирающий» бот пытается переоткрыть позиции, которые закрывает скрипт остановки.
2.  **Hedge Mode API Fix (No reduceOnly):** В `executor.py` и `connector.py` полностью удалена передача параметра `reduceOnly` для реальных API-запросов. В режиме хеджирования (Hedge Mode) этот параметр не поддерживается и вызывает ошибку `-1106`. Защита от открытия встречных позиций теперь обеспечивается строго через корректную комбинацию `side` и `positionSide`. (Для бумажной торговли логика `reduce_only` сохранена для расчетов PnL).
3.  **Zero-Dust Closing:** В режиме `emergency_stop` параметр `min_notional` принудительно сбрасывается в **0.0**. Это позволяет системе закрывать даже микро-позиции («пыль»), которые ранее могли быть пропущены из-за фильтра минимальной стоимости в 6.0 USDT.
4.  **Sequential Rotation:** В `supervisor.py` добавлены защитные паузы (`asyncio.sleep`) между этапами остановки и запуска, обеспечивая последовательность «Stop -> Verify -> Start» и давая API Binance время на обработку всех транзакций.

## 🗓 02 мая 2026: Исправление регрессии логики ребалансировки (v2.3)

### ✅ Ключевые исправления:
1.  **Drift Detection Restoration:** Устранена ошибка «маскировки дрейфа», вызванная принудительным пропорциональным распределением Margin Balance. Теперь `val_long` и `val_short` рассчитываются на базе их **реальной рыночной стоимости** (Collateral Basis + Unrealized PnL), что позволяет системе корректно фиксировать перекосы при движении цены.
2.  **Anti-Procyclical Fix:** Исправлена ошибка, из-за которой система работала «про-циклично» (покупала при росте), используя только Notional / Leverage для оценки веса. Новая модель учитывает полный PnL, возвращая классическую контр-циклическую логику ребалансировки.
3.  **Zero-State Initialization:** Исправлен баг, блокировавший открытие позиций «с нуля». Система больше не предполагает, что целевые веса достигнуты, если позиций нет.
4.  **Parameter Synchronization:** В `main.py` добавлена передача `long_entry_price` и `short_entry_price` в математический движок. Это критически важно для расчета PnL в реальном времени.
5.  **Cash Transparency:** В логи heartbeat и расчеты долей добавлен компонент `CASH`. Теперь сумма долей L+S+V+Cash всегда равна 100% TPV, обеспечивая полную прозрачность структуры капитала.
6.  **Backtest Alignment:** Бэктестер `backtest_rebalance.py` полностью синхронизирован с исправленной логикой бота, обеспечивая идентичность результатов тестирования и реальности.
7.  **Test Verification:** Обновлен и успешно пройден набор тестов в `test_calculator.py`.

5.  **System-Wide Unit Unification:** Все временные параметры окончательно унифицированы и переведены в **дни** (probation, backtest, supervisor, scanner).
