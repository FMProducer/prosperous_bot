# Futures Rebalance Bot (Gamma-Pump Protocol v3.7.8)

## Описание: Математическая доктрина и Mark-to-Market

Система управляет портфелем как **единым, неразрывным математическим пространством**, работающим по принципу сообщающихся сосудов. Алгоритм реализует стратегию **Mark-to-Market (MTM) Rebalancing**, где каждая секунда движения цены изменяет рыночную стоимость активов и, следовательно, их долю в общем капитале.

В основе лежит принцип **Delta-Neutrality**: суммарная экспозиция портфеля на рост рынка должна быть полностью скомпенсирована экспозицией на падение, превращая портфель в «контейнер волатильности».

### 1. Фундаментальный инвариант и Дельта-Нейтральность
Портфель состоит из четырех компонент, сумма рыночных стоимостей (Equity) которых строго равна 100%:
$$Weight_L + Weight_S + Weight_V + Weight_{Cash} \equiv 100.0\%$$

*   **Long (L):** Реальная фьючерсная позиция (плечо x5, цель ~29%).
*   **Short (S):** Реальная фьючерсная позиция (плечо x5, цель ~36%).
*   **Virtual (V):** Полный математический аналог владения базовым активом на споте (плечо x1, цель ~35%). Трактуется как **физическое количество монет**, меняющее свою стоимость синхронно с рынком.
*   **Cash (C):** Свободный остаток USDT в кошельке (резерв ликвидности).

**Математическое доказательство Delta = 0:**
*   Экспозиция Long: $29\% \times 5 = 145\%$
*   Экспозиция Virtual: $35\% \times 1 = 35\%$
*   Суммарный Long: $145\% + 35\% = 180\%$
*   Экспозиция Short: $36\% \times 5 = 180\%$
*   **Итоговая Дельта:** $180\% (L+V) - 180\% (S) = 0$

### 2. Принцип и Приоритеты Ребалансировки
Система работает по принципу «насоса»: она извлекает прибыль из «трения» (волатильности) активов, когда они отклоняются от целевых весов.

1.  **Mark-to-Market Оценка (TPV):**
    $$TPV = \text{Wallet Balance} + \text{PnL}_L + \text{PnL}_S + (\text{Quantity}_V \times \text{Price}_{Spot})$$
    Это полная ликвидационная стоимость портфеля в моменте.
2.  **Независимый Триггер (Independent Threshold):** Каждая нога (L, S, V) проверяется отдельно. Ребалансировка инициируется только для той ноги, чье отклонение от цели превысило `rebalance_threshold` (например, 3.5%).
3.  **Алгоритм «Сначала продай — потом купи»:**
    *   **Шаг 1 (Surplus/SELL):** Все ноги с избытком стоимости (Deviation >= +3.5%) формируют пул выручки. Они исполняются первыми (**Priority 0**) и физически наполняют Cash.
    *   **Шаг 2 (Cash Guard):** Бот рассчитывает `Available_Funds = Current_Cash + Proceeds_from_Sells`. Покупки совершаются только на эти деньги. Бот никогда не торгует «в долг» (в минус по кэшу).
    *   **Шаг 3 (Deficit/BUY):** Ноги с дефицитом (Deviation <= -3.5%) претендуют на доступный кэш.
4.  **Иерархия Финансирования (Funding Priority):**
    *   **Приоритет 1:** Виртуальная доля (V). Она доводится до целевых 35% первой.
    *   **Приоритет 2:** Фьючерсные ноги (L, S). Они получают остатки кэша.
    *   *Примечание:* Если кэша не хватает на полный возврат к цели, бот делает частичную покупку (но не менее чем на `min_notional` 6.1 USDT).

### 3. Особенности Virtual Leg и Dust Guard
Virtual-нога — это полноценный спотовый актив внутри системы:
*   **No Entry Price:** У неё нет фиксированной цены входа. Её профит — это изменение её рыночной массы относительно выделенного под неё капитала.
*   **Cash Accounting:** Каждая «виртуальная покупка» сопровождается реальным списанием USDT из бумажного баланса (Shadow Cash), а продажа — начислением.
*   **Dust Guard:** Если рыночная стоимость виртуальной позиции опускается ниже 1.0 USDT, она принудительно ликвидируется в Cash, предотвращая накопление «пыли».

### 4. Heartbeat и Прозрачность данных
Лог Heartbeat спроектирован так, чтобы пользователь мог мгновенно проверить математику портфеля в уме:
`L:29.0% [+0.0%] {+29.00$} | S:36.0% [+0.0%] {+36.00$} | V:35.0% [+0.0%] {+35.00$} | C:0.0% {+0.00$}`
*   **В скобках `{}`:** Абсолютная рыночная стоимость (Equity) компонента.
*   **Контрольная сумма:** Сумма всех долларовых значений в `{}` **строго равна TPV**.
*   **В скобках `[]`:** Отклонение от цели. Знак % совпадает со знаком $ PnL (относительно точки последней ребалансировки).

### 5. Безопасность и Стабильность
*   **Velocity Guard:** Блокировка сделок при резких свечах (импульс > 1.0% за 60 сек).
*   **Spread Guard:** Проверка ликвидности стакана (спред < 0.15%) перед ордером.
*   **Anti-Churn Fuse:** Запрет сделок, не улучшающих среднюю цену (Buy Low, Sell High) относительно предыдущей точки баланса.
*   **Shadow Isolation:** Полное разделение бумажного и реального балансов для каждого тикера, позволяющее запускать десятки ботов на одном аккаунте без конфликтов.


## Структура проекта

## Установка
1. Клонируйте репозиторий или скопируйте папку `futures_portfolio`.
2. Создайте виртуальное окружение (рекомендуется Python 3.10+):
   ```powershell
   python -m venv venv
   .\venv\Scripts\activate
   ```
3. Установите зависимости:
   ```powershell
   pip install -r requirements.txt
   ```

## Конфигурация
Отредактируйте `config.json`:
- `api_key` и `secret_key` — ваши учетные данные Binance.
- `testnet` — `true` для тестовой сети, `false` для продакшена.
- `portfolios[].targets` — целевые доли активов (сумма должна быть 1.0).
- `portfolios[].rebalance_threshold` — порог отклонения (по умолчанию 0.02 = 2%).
- `portfolios[].check_interval_sec` — интервал проверки в секундах.
- `tickers` — список трейдинговых пар.

## Запуск
```powershell
python main.py --config config.json --interval 60
```
Параметры:
- `--config` — путь к конфиг-файлу (по умолчанию `config.json`).
- `--interval` — интервал проверки в секундах (по умолчанию 60).

Логи будут записаны в `logs/rebalance.log`.

## Тестирование
Для запуска unit-тестов:
```powershell
pytest
```
Тесты проверяют расчёты в `calculator.py` и `executor.py` с использованием моков.

## Важно
- Перед запуском на реальном аккаунте убедитесь, что `testnet` установлен в `true` и протестируйте на Testnet.
- Обработка ошибок и точная настройка `reduceOnly` могут быть доработаны в дальнейшем.
- Текущая реализация не включает точное округление количества контрактов (precision) — это может быть добавлено при необходимости.
