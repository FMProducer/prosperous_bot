# Futures Rebalance Bot

## Описание: Математическая доктрина «Синхронные часы» (v3.3.0)

Система управляет портфелем как **единым, неразрывным математическим пространством**, работающим по принципу сообщающихся сосудов. В отличие от классических ботов, торгующих "сигналы", этот алгоритм поддерживает жесткий инвариант структуры капитала.

### 1. Фундаментальный инвариант
Портфель всегда состоит из четырех компонент, сумма весов которых строго равна 100%:
$$Weight_L + Weight_S + Weight_V + Weight_{Cash} \equiv 100.0\%$$

*   **Long (L):** Реальная позиция на фьючерсах (плечо x5).
*   **Short (S):** Реальная позиция на фьючерсах (плечо x5).
*   **Virtual (V):** Математический аналог владения базовым активом (плечо x1). Трактуется как **физическое количество монет на споте**, которое меняет свою стоимость синхронно с рынком.
*   **Cash (C):** Свободный остаток USDT (резерв для ребалансировок).

### 2. Принцип ребалансировки
Система не фиксирует прибыль в классическом понимании. Вместо этого происходит **непрерывное перераспределение стоимости**:

1.  **Живая оценка TPV (Total Portfolio Value):** 
    $$TPV = \text{Equity}_{Real} + (\text{Quantity}_V \times \text{Price}_{Spot})$$
    Любое изменение цены тикера мгновенно меняет TPV через Virtual-ногу и PnL реальных позиций.
2.  **Дрейф долей:** При изменении цены доли L, S и V начинают отклоняться от целевых (например, 29%, 36%, 35%).
3.  **Синхронный импульс:** Как только отклонение любой доли превышает `rebalance_threshold`, запускается цикл выравнивания:
    *   Избыточная стоимость из "выросших" долей (включая Virtual) физически перемещается в **Cash**.
    *   Из **Cash** докупаются "просевшие" доли до их целевых значений.
4.  **Реализация прибыли:** Прибыль от Virtual-ноги и хеджированных позиций не "растворяется", а оседает на балансе Cash, увеличивая базу для следующего цикла.

### 3. Virtual Leg как спотовый актив
Virtual-нога — это не дериватив. Она не имеет "цены входа". Система оперирует **количеством единиц** (Quantity). Ребалансировка Virtual-ноги — это имитация продажи/покупки монет на споте для поддержания её доли в 35% от общего TPV.

### 4. Цель системы
Создание рыночно дельта-нейтрального контейнера, который извлекает прибыль из **внутренней волатильности** (трения) между плечевым хеджем и спотовым активом, сохраняя при этом полную прозрачность и математическую целостность капитала.


## Структура проекта
```
futures_portfolio/
├── main.py               # Асинхронный цикл ребалансировки
├── config.json           # Конфигурация портфеля
├── requirements.txt      # Зависимости
├── connector.py          # Инициализация Binance Futures и Spot клиентов
├── calculator.py         # Расчёт стоимости, долей, отклонений
├── executor.py           # Расчёт ордеров и отправка на Binance Futures
├── logs/
│   └── rebalance.log     # Логи ребалансировки
└── tests/
    ├── test_calculator.py
    └── test_executor.py
```

## Установка
1. Клонируйте репозиторий или скопируйте папку `futures_portfolio`.
2. Создайте виртуальное окружение (рекомендуется Python 3.10+):
   ```powershell
   python -m venv venv
   .\venv\Scripts\activate
   ```
3. Установите зависимости:
   ```powershell
   pip install -r requirements.txt
   ```

## Конфигурация
Отредактируйте `config.json`:
- `api_key` и `secret_key` — ваши учетные данные Binance.
- `testnet` — `true` для тестовой сети, `false` для продакшена.
- `portfolios[].targets` — целевые доли активов (сумма должна быть 1.0).
- `portfolios[].rebalance_threshold` — порог отклонения (по умолчанию 0.02 = 2%).
- `portfolios[].check_interval_sec` — интервал проверки в секундах.
- `tickers` — список трейдинговых пар.

## Запуск
```powershell
python main.py --config config.json --interval 60
```
Параметры:
- `--config` — путь к конфиг-файлу (по умолчанию `config.json`).
- `--interval` — интервал проверки в секундах (по умолчанию 60).

Логи будут записаны в `logs/rebalance.log`.

## Тестирование
Для запуска unit-тестов:
```powershell
pytest
```
Тесты проверяют расчёты в `calculator.py` и `executor.py` с использованием моков.

## Важно
- Перед запуском на реальном аккаунте убедитесь, что `testnet` установлен в `true` и протестируйте на Testnet.
- Обработка ошибок и точная настройка `reduceOnly` могут быть доработаны в дальнейшем.
- Текущая реализация не включает точное округление количества контрактов (precision) — это может быть добавлено при необходимости.
