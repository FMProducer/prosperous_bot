# Binance Futures Portfolio Rebalancer

Асинхронный инструмент на Python для автоматического поддержания рыночно-нейтрального портфеля на фьючерсном аккаунте Binance.

## 📌 Описание системы: Market Neutral 2.0
Система реализует стратегию динамического синтетического хеджирования. Портфель имитирует владение BTC (или другим активом) без покупки на споте, используя свободную маржу аккаунта как третью активную ногу баланса.

### Целевое распределение (Market Neutral):
1.  **Long x5 (29%)**: Длинная позиция на фьючерсах.
2.  **Short x5 (36%)**: Короткая позиция на фьючерсах.
3.  **Margin Simulation (35%)**: Виртуальная позиция BTC (x1), работающая на свободной марже.

## 🏗 Архитектура и Логика работы

### 1. Используемые данные (Input Data)
Для автономной работы бот запрашивает следующие данные через API Binance Futures:
*   **Рыночные данные:**
    *   `Mark Price`: Цена маркировки для расчета PnL и TPV.
    *   `Klines (1m)`: Свечной график для расчета ATR (волатильности).
    *   `Exchange Info`: Параметры контракта (`stepSize`, `minNotional`) для корректного формирования ордеров.
*   **Данные аккаунта:**
    *   `Available Balance`: Свободная маржа в USDT.
    *   `Position Amount`: Количество актива в Long и Short.
    *   `Unrealized PnL`: Текущая плавающая прибыль/убыток.

### 2. Ключевые метрики (Calculated Metrics)
На основе входных данных система вычисляет:
*   **Real Equity:** `Available_Balance + Sum(Unrealized_PnL)`. Фактические средства на аккаунте.
*   **TPV (Total Portfolio Value):** Истинная стоимость портфеля с учетом "виртуальной" ноги.
    *   `TPV = Real_Equity + (Virt_Current_Value - Virt_Allocated_USDT)`.
*   **TPV_Active:** Рабочий капитал (`TPV - siphoning_reserve`). База для расчета лотов.
*   **ATH (All-Time High):** Максимальное зафиксированное значение TPV за все время сессии.
*   **Dynamic Threshold:** Текущий порог ребалансировки, адаптированный под ATR.

## 🛡 Механизм «Сейфа» (Profit Siphoning)
Для обеспечения стабильного роста эквити и защиты капитала внедрена система автоматической фиксации прибыли.

### Принцип работы:
1.  **Настройка:** Через параметр `siphoning_threshold_pct` в `config.json` задается порог (например, 0.5%).
2.  **Резервирование:** При превышении порога доходности активного капитала, излишек автоматически переносится в `siphoning_reserve`.
3.  **Реинвестирование:** Параметр `reinvestment_ratio` (0.0 - 1.0) определяет, какая часть прибыли идет на увеличение рабочих лотов, а какая — в "сейф".

## 📊 Стратегия выбора активов (Selection Strategy)
На основе анализа циклов ребалансировки и волатильности выведены критерии идеального тикера:

1.  **Циклы (Cycles):** Минимум **> 500** за 24 часа в `rank_tickers.py`.
2.  **Фактор "Пилы" (Trend Efficiency):** Оптимально **< 3.0%**. Если тренд > 10%, актив становится опасным.
3.  **Энергия (Volatility):** Суточный размах **> 35%**.
4.  **Фандинг (Funding):** Предпочтительно положительный (доп. доход для Short-ноги).

## 🚀 Операционный Workflow: «24-часовой спринт»
Для максимизации прибыли и минимизации рисков рекомендуется придерживаться ежедневного цикла ротации:

### Шаг 1: Сканирование (Scanner)
Запустите `rank_tickers.py` для поиска лидеров волатильности:
`python rank_tickers.py`
*Критерий:* Ищите активы из **Tier-1 (GOLD)** со SCORE > 500 и TREND < 3%.

### Шаг 2: Live-верификация (Filter)
Проверьте лидера рейтинга на реальных свечах за последние 24 часа:
`python backtest_rebalance.py --live --ticker MOVRUSDT`
*Критерий запуска:* **NET PROFIT (FEES) > +0.5%** за последние 24 часа.

### Шаг 3: Запуск (Execution)
Обновите `config.json` (поле `base_ticker`) и запустите бота на 24 часа:
`python main.py`

### Шаг 4: Ротация (Rotation)
Через 24 часа остановите бота, зафиксируйте профит и вернитесь к Шагу 1. Это защищает от перехода актива в затяжной направленный тренд.

## 🛠 Улучшения и изменения (16-18 апреля 2026)

### Безопасность и риск-менеджмент
*   **Equity Trailing Stop (Profit-Activated):** Защита прибыли от резких откатов эквити. Порог **10.0%** является оптимальным.
*   **Soft Hysteresis (Мягкий гистерезис):** Удвоение порога ребалансировки при `TPV < initial_tpv`. Снижает комиссии на 40% в зоне просадки.
*   **Dynamic Threshold (ATR-based):** Автоподстройка под текущую волатильность.
*   **Live Backtesting Engine:** В `backtest_rebalance.py` внедрен движок прямой загрузки данных с Binance (флаг `--live`). Позволяет мгновенно проверить доходность любого тикера за последние 24 часа перед реальным запуском.
*   **Smart Ticker Scanner (`rank_tickers.py`):** Интеллектуальный инструмент выбора активов по "Золотым правилам" (Cycles/Trend/Vola/Funding).
*   **Ticker Switch Safety:** Автоматический сброс базиса, очистка старых позиций и сброс `initial_tpv` при смене актива в `main.py`.
